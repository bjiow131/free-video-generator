# Подключение GitHub mailbox на Windows

## Что обнаружено и исправлено в этой ветке

В local_agent/poller.py был ранний return: функция сразу сообщала, что GitHub mailbox отключён, и возвращала код 2. Ниже оставался старый код опроса, но нужные импорты GitHub-клиента, конфигурации, сетевой ошибки и локального outbox отсутствовали. Поэтому соединение не могло запуститься даже после простого удаления return.

Исправление добавляет недостающие импорты и оставляет GitHub-опрос выключенным по умолчанию. Отдельный файл run_github_mailbox_agent.bat включает режим явно. Обычный run_blender_agent.bat не должен автоматически запускать удалённый опросчик.

## 1. Подготовить доступ

GitHub CLI для этого конкретного mailbox не требуется: существующий клиент использует GitHub REST API и Windows Credential Manager.

1. В GitHub создайте fine-grained personal access token с доступом только к приватному репозиторию bjiow131/local-agent-mailbox.
2. Дайте минимально необходимые права Contents: Read and write. Чтение нужно для queue/desired_task.json, запись — для queue/results/<task_id>.json.
3. В PowerShell из корня репозитория выполните:

    python -m local_agent.credentials_cli set

4. Введите токен дважды. Ввод скрыт; токен сохраняется в Windows Credential Manager и не печатается.
5. Проверьте наличие учётных данных:

    python -m local_agent.credentials_cli status

Эти шаги требуют нормального доступа к GitHub. Не помещайте токен в исходники, .env, JSON, командную строку или логи. Не обходите проверки GitHub и SMS-верификацию.

## 2. Проверить конфигурацию без запуска задач

Убедитесь, что в приватном репозитории существует queue/desired_task.json на ветке main. Запускатель задаёт безопасные значения по умолчанию:
- LOCAL_AGENT_GITHUB_REPO=bjiow131/local-agent-mailbox
- LOCAL_AGENT_GITHUB_REF=main
- LOCAL_AGENT_GITHUB_MANIFEST=queue/desired_task.json (значение клиента по умолчанию)

Если переменные окружения заданы ранее, они имеют приоритет. Проверьте, что они указывают на правильный приватный репозиторий и ветку.

## 3. Запуск

Дважды нажмите run_github_mailbox_agent.bat или запустите его из PowerShell. Опросчик должен сообщить, что опрашивает приватный GitHub mailbox. При каждой новой задаче он выводит задачу и требует локального подтверждения, набрав YES. Не подтверждайте неизвестную задачу.

Если появится ошибка авторизации, проверьте права токена и доступ к приватному репозиторию. Если появится ошибка отсутствующего manifest, проверьте repository/ref/path. Не публикуйте содержимое токена или полный вывод, если в нём есть личные данные.

## 4. Куда отправляются результаты

Результат задачи сначала сохраняется в локальный outbox внутри .local_agent/pending_results. После успешного ответа GitHub он записывается в queue/results/<task_id>.json в mailbox-репозитории. При сетевой ошибке файл остаётся локально, и опросчик повторяет отправку; задача не должна запускаться повторно только из-за сбоя публикации.

## Статус проверки

Ветка исправляет очевидные причины отключения и добавляет тест на безопасный режим по умолчанию. Реальная авторизация Windows, live round-trip и запуск Blender в этой среде не выполнялись. Перед использованием требуется прогнать тесты и проверить соединение на компьютере.

## 5. Проверка канала без выполнения удалённой задачи

После сохранения токена выполните:

    python scripts/check_github_connection.py

Скрипт проверяет доступ к приватному репозиторию и записывает безвредный результат проверки в queue/results/connection-check-<UTC-время>.json. Он **не читает и не выполняет** очередь desired_task.json. При успехе вы увидите status=connected и ссылку на путь результата; при ошибке будут показаны только тип ошибки и короткое безопасное сообщение.
